# Implementation plan

## Phase 1 — Review prototype (current)

- Create a polished, responsive operations cockpit under the provisional Fieldline name.
- Model the full lifecycle in one realistic job: intake, private sourcing, pricing/approval, assignment, scheduling, change-order controls, evidence, invoices, and closeout.
- Include distinct routine and emergency paths, vendor compliance gates, gross-margin calculation, and immutable-feeling NTE history.
- Make core review moments interactive so managers and vendors can react to behavior, not static screens.

## Phase 2 — Pilot learning

- Replace sample records with three anonymized jobs collected with Zak.
- Run structured review sessions with fewer than five customers, fewer than five vendors, and the pilot FDI team.
- Validate roles, terminology, notification expectations, emergency handling, and what must remain private.
- Decide prototype name and add the supplied FDI identity assets.

## Phase 3 — Production definition

- Convert validated flows into role-based requirements and an integration map.
- Define ServiceChannel/customer-system intake, email intake, document storage, notifications, audit log, and QuickBooks Online handoff.
- Specify security, retention, vendor onboarding, operational reporting, and data migration before choosing production infrastructure.

## Deliberately deferred

Payment processing, bank/card collection, public vendor discovery, automatic low-bid awards, a forced FM-to-CapEx transfer, and production integrations.
